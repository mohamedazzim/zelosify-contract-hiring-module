## Benchmark result (mocked provider)

Run via `npx vitest run --config vitest.performance.config.ts` — 100 profiles, deterministic mocked LLM with controlled 150–350ms latency per call, async worker pool of 3 (matches production `MAX_CONCURRENCY = 3`), SLA 1500ms, real queue + service code paths (Prisma/storage mocked).

- **P50:** 770.0ms
- **P95:** 907.0ms
- **Max:** 1029.0ms
- **Max concurrency observed:** 3 (bounded, matches production `MAX_CONCURRENCY`)
- **SLA breaches (>1500ms):** 0
- **Queue wait time vs processing latency:** reported separately (in-process enqueue is immediate; per-profile processing latency measured under the 3-worker pool)
- **Durable attempts:** max attempts per profile remained at 1 in the run; the 3-attempt cap enforced by claim logic (asserted in `durableAttempts.unit.test.ts`)

*This is a mocked benchmark (no paid/external LLM calls). P95 < 2000ms holds under controlled provider latency; a real Groq run requires a live `GROQ_API_KEY` and is not part of automated tests.*
